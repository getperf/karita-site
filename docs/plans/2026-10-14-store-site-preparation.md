# Store公開に向けたサイト整備方針・導入ガイド構成案

作成日: 2026-10-14
状態: 方針・構成案。公開用本文や操作検証の完了を表すものではない。

## 1. 背景と進め方

karita Windows版はMicrosoft StoreへPrivate audience・無料・日本市場・日本語・18+で提出済み。まずStore配布版のインストールを検証し、ブラウザ拡張の公開を進め、その結果を反映してサイトを整備する。待機中に最小構成と導入手順の原稿を用意する。一般公開への切り替えは別の判断とする。

karitaは単独のアプリ画面だけで作業が完結する製品ではない。カーリルで探す、図書館サイトで実際の予約・貸出状況を確認する、Amazonで本を見る、ブラウザ拡張からkaritaへ戻して記録する、という複数画面の往復が利用体験の中心になる。サイトは機能一覧よりも「今どの画面で何を操作し、次にどこへ戻るか」を厚く説明する。

Windowsでこの往復を使う標準導入は、karita本体とブラウザ拡張「karita に送る」の両方のインストールを前提にする。拡張が不要と誤解させない。一方、URL貼り付け・手動入力の代替経路も示し、アプリの全機能が拡張なしでは起動できないという説明にはしない。

## 2. 審査期間と言語

MicrosoftのMSIX向け案内は審査に最大3営業日程度、通過後の掲載反映は平均15分程度。確約ではなく、追加確認や再提出で延び得る。2026-10-14提出分は週末を含む10月19日ごろを状況確認の目安にする。Private audienceの掲載完了は一般公開を意味しない。

日本語を主言語とし、サイト全体の英訳は初期範囲に含めない。今回確認したWindowsアプリ向け資料では外部サイト全体の英語化義務は確認していない。審査担当者向けに短い英語の操作ガイドを追加することを推奨する。これは審査通過を保証する措置ではない。

提出済みの英語審査メモと公開ページの内容を揃える。日本の図書館向け・日本語UI・Googleアカウントが必要な機能・外部サイト依存・予約結果が自動反映されないことを説明する。アカウント情報を公開サイトへ置かない。審査でテストアカウントを求められた場合はPartner Centerの非公開欄で対応する。

公式資料（2026-10-14確認）:

- [MSIXの審査工程](https://learn.microsoft.com/en-us/windows/apps/publish/publish-your-app/msix/app-certification-process)
- [審査用メモと提出オプション](https://learn.microsoft.com/en-us/windows/apps/publish/publish-your-app/msix/manage-submission-options#notes-for-certification)

## 4. getting-startedの詳細構成案

### 4.1 全体像と準備

最初に「karita → ブラウザ → 外部サイト → 拡張 → karita」の図を置く。以後の各手順にも操作場所を表示する。

- Windows本体と、使用するブラウザの拡張の両方が必要であることを冒頭に掲載する。
- Store用Microsoftアカウント、同期用Googleアカウント、図書館サイトの利用者アカウントは役割が異なると説明する。
- 図書館の予約・更新・取消など実際の手続きは図書館サイトで行う。karitaへの送信は手続きの代行・成功証明ではない。
- 対応Windows・ブラウザ・本体と拡張の組み合わせは配布版の検証結果で確定する。

### 4.2 本体と拡張のインストール

1. 公開状態に応じたStore案内から本体をインストールし、起動する。
2. 使用ブラウザ用の拡張を入れ、ツールバーへ固定する。Chrome／Edge／Firefoxの配布方法・状態を個別に記載する。
3. 書籍ページから送信し、ブラウザの外部アプリ起動確認を経てkaritaが開くことを確認する。
4. 開かない場合は拡張内の再試行リンクを使う。現在の表示は「karita を開く」。配布版の実画面で表記を確認する。

一般向け手順へ開発者モード・テスト証明書の信頼設定を標準手順として載せない。Store署名版ではテストMSIX用証明書は不要。Private audienceのアカウント限定リンクは別のテスター案内で扱う。

### 4.3 初回セットアップと同期

Googleサインイン、同意画面、利用する図書館・地区の設定、新規開始と既存データ同期の選択を説明する。画面ラベル・順序はStore版で確認してから確定する。検証用Googleアカウントと日常データを混同しない。新規環境のセットアップは未確認なので、成功確認済みと記載しない。

### 4.4 予約のhandoff（重点）

利用者向けにはhandoffを「ブラウザからkaritaへ情報を渡して戻る操作」と説明する。

1. カーリルの書籍ページで対象の本と図書館を確認する。
2. 図書館サイトへ移動し、予約手続きを行い、図書館サイト側の結果を確認する。
3. 図書館タブで拡張を開き、取得できる場合は「元のカーリル書籍を karita に送る」を選ぶ。
4. 元の書籍を取得できない場合はカーリルの書籍タブへ戻って送る。必要に応じて「カーリルタブの読み取りを許可」の権限案内を示す。
5. karitaで対象の本・図書館・記録内容を確認し、利用者が確定する。

スクリーンショットはカーリル書籍、図書館側の結果確認箇所、拡張の選択、karitaの記録確認を対にする。図書館ごとに画面が異なることを注記する。カーリルの検索結果・トップページを送る手順にしない。「現在のページのURL」と「元の書籍」は用途が異なる。親タブが閉じられた場合や別ウィンドウの場合も説明する。

### 4.5 貸出しのhandoff（重点）

1. karitaの対象図書館・地区から図書館サイトを開く、または図書館サイトへ直接アクセスする。
2. 図書館サイトで貸出中の本・返却期限などを確認する。
3. 拡張の「貸出し画面（図書館別）に移動」を選んでkaritaへ戻る。
4. 用途・地区の確認が出た場合は対象を選び、該当図書館の貸出し画面で実際の状況と照合・記録する。

送信だけで貸出一覧・期限・返却状態を取得して自動更新するとは説明しない。マイページURLの登録は別操作として区別し、安定した入口URLを利用者が確認して登録する。セッション付きURLを保存・公開する例を載せない。

### 4.6 Amazonとの往復

- karita本棚の「Amazonで見る」からブラウザを開き、拡張で送って戻る操作を案内する。
- Amazonから直接送った場合は、ISBNや既存の記録によって、本棚の本・予約の下書き・案内表示などに分岐する。無条件に本棚へ追加されるとは書かない。
- 対象はAmazon.co.jpのブラウザ上の紙の本の商品ページを基本とする。Kindle・短縮URL・Amazonアプリ共有・検索結果を同等に対応済みとしない。
- 購入・注文情報の取得や購入結果の自動反映を行う機能とは説明しない。

### 4.7 送れない場合と次の一歩

未起動時と起動中の操作、外部アプリ起動確認、拡張の再試行、URL貼り付け・手動入力、間違った本・地区を選んだときの戻り方、同期確認、サポートへの入口を短く載せる。

## 5. 注意点と公開前確認

- 配布状態は「実装済み」「検証済み」「公開済み」を分ける。未公開のストアリンクや準備中の機能を利用可能と見せない。
- 本体のStore版と開発版・テストMSIXの併存によるURI起動先の混同を検証する。利用者向けには確認方法と対処を絞って記載する。
- 拡張のカーリル権限は親書籍の取得を助けるためのもの。閲覧履歴全体へのアクセスが必要という案内にしない。
- 図書館カード番号、氏名、メール、貸出履歴、セッション付きURL、認証情報をスクリーンショットへ残さない。第三者サイトの画面利用条件も確認する。
- プライバシーポリシーのWindows認可情報「DPAPI相当」は本体の未実装方針と不一致。実装を確認し、事実に合わせる。
- アンインストールによるデータ即時削除は、既存環境の保存先も含めて再確認する。一律に断定しない。
- Driveバックアップの削除方法をGoogle側の管理操作・アプリ実装と照合する。「利用者にも削除できない」と未確認のまま断定しない。
- Firefoxを含む対象ソフトの説明をホーム・ポリシー・拡張ページで統一する。
- 一般公開前の本体側残件はkarita-coreのStore計画を正本とし、本書だけで解決済みにしない。
